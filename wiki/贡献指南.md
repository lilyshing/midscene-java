## 🛠️ 开发环境设置

- JDK 17 或更高版本

## 📝 代码规范

### Java 代码规范

我们遵循 [Google Java Style Guide](https://google.github.io/styleguide/javaguide.html) 并有以下额外规定：

1. **命名规范**：
   - 类名：PascalCase（例如 `PlaywrightPage`）
   - 方法名：camelCase（例如 `aiAction`）
   - 常量：UPPER_SNAKE_CASE（例如 `MAX_RETRIES`）
   - 变量：camelCase（例如 `elementId`）

2. **注释规范**：
   - 公共类和方法必须有 Javadoc 注释
   - 复杂逻辑必须有行内注释
   - TODO 注释格式：`TODO: 描述`

3. **异常处理**：
   - 使用具体的异常类型
   - 提供有意义的错误消息
   - 记录异常堆栈

4. **日志规范**：
   - 使用 SLF4J 日志框架
   - 使用适当的日志级别
   - 避免在循环中记录日志

### 示例代码

```java
/**
 * 使用 Playwright 实现的页面类。
 * 
 * <p>提供页面导航、元素操作和页面信息提取等功能。
 * 
 * @author Midscene Team
 * @since 1.0.0
 */
public class PlaywrightPage implements Page {
    private static final Logger logger = LoggerFactory.getLogger(PlaywrightPage.class);
    private static final int DEFAULT_TIMEOUT = 30000; // 30秒
    
    private final com.microsoft.playwright.Page page;
    
    /**
     * 创建一个新的 PlaywrightPage 实例。
     * 
     * @param page Playwright 页面实例
     * @throws IllegalArgumentException 如果 page 为 null
     */
    public PlaywrightPage(com.microsoft.playwright.Page page) {
        if (page == null) {
            throw new IllegalArgumentException("Page cannot be null");
        }
        this.page = page;
    }
    
    /**
     * 导航到指定的 URL。
     * 
     * @param url 要导航的 URL
     * @return 导航操作的 CompletableFuture
     * @throws NavigationException 如果导航失败
     */
    @Override
    public CompletableFuture<Void> navigate(String url) {
        logger.debug("Navigating to URL: {}", url);
        
        return CompletableFuture.runAsync(() -> {
            try {
                page.navigate(url);
                logger.info("Successfully navigated to URL: {}", url);
            } catch (Exception e) {
                logger.error("Failed to navigate to URL: {}", url, e);
                throw new NavigationException("Failed to navigate to: " + url, e);
            }
        });
    }
    
    // 其他方法...
}
```

## 📦 提交规范

### 提交消息格式

我们使用 [Conventional Commits](https://www.conventionalcommits.org/) 规范：

```
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

### 类型说明

- `feat`: 新功能
- `fix`: 修复 bug
- `docs`: 文档更新
- `style`: 代码格式化（不影响功能）
- `refactor`: 代码重构
- `test`: 添加或修改测试
- `chore`: 构建过程或辅助工具的变动

### 示例提交消息

```bash
feat(web): add support for Firefox browser

Add support for Firefox browser in the web automation module.
This includes:
- Firefox browser initialization
- Firefox-specific element handling
- Firefox-specific wait strategies

Closes #123
```

```bash
fix(android): resolve element location issue on Android 10

Fix element location issue on Android 10 devices by updating
the UIAutomator selector strategy. This issue was caused by
changes in the Android 10 UI hierarchy.

Closes #456
```

### 提交步骤

1. **暂存更改**：
   ```bash
   git add .
   ```

2. **提交更改**：
   ```bash
   git commit -m "feat(core): add new AI model integration"
   ```

3. **推送更改**：
   ```bash
   git push origin feature/new-ai-model
   ```

## 🧪 测试指南

### 测试结构

项目测试分为以下几类：

1. **单元测试**：
   - 位置：`src/test/java`
   - 命名：`*Test.java`
   - 框架：JUnit 5

2. **集成测试**：
   - 位置：`src/test/java`
   - 命名：`*IntegrationTest.java`
   - 框架：JUnit 5 + TestContainers

3. **端到端测试**：
   - 位置：`src/e2e-test/java`
   - 命名：`*E2ETest.java`
   - 框架：JUnit 5

### 编写测试

1. **单元测试示例**：
   ```java
   import org.junit.jupiter.api.Test;
   import org.junit.jupiter.api.BeforeEach;
   import static org.junit.jupiter.api.Assertions.*;
   
   class PlaywrightPageTest {
       private PlaywrightPage page;
       
       @BeforeEach
       void setUp() {
           // 初始化测试环境
           page = new PlaywrightPage(mockPlaywrightPage);
       }
       
       @Test
       void shouldNavigateToUrlSuccessfully() {
           // Given
           String url = "https://example.com";
           
           // When
           CompletableFuture<Void> result = page.navigate(url);
           
           // Then
           assertDoesNotThrow(() -> result.join());
           verify(mockPlaywrightPage).navigate(url);
       }
       
       @Test
       void shouldThrowExceptionWhenUrlIsNull() {
           // Given
           String url = null;
           
           // When & Then
           assertThrows(IllegalArgumentException.class, () -> page.navigate(url));
       }
   }
   ```

2. **集成测试示例**：
   ```java
   @ExtendWith(TestcontainersExtension.class)
   class WebAutomationIntegrationTest {
       @Container
       static final BrowserContainer browser = new BrowserContainer()
           .withBrowserType("chromium");
       
       private Agent agent;
       
       @BeforeEach
       void setUp() {
           PlaywrightPage page = new PlaywrightPage(browser.getPage());
           PlaywrightUIContextProvider provider = new PlaywrightUIContextProvider(page);
           agent = new Agent(provider);
       }
       
       @Test
       void shouldPerformWebAutomationSuccessfully() {
           // Given
           String searchQuery = "Midscene Java";
           
           // When
           agent.ai_action("导航到 https://www.google.com").get();
           agent.ai_action("在搜索框中输入: " + searchQuery).get();
           agent.ai_action("点击搜索按钮").get();
           
           // Then
           boolean searchResultsDisplayed = agent.ai_assert("显示搜索结果").get();
           assertTrue(searchResultsDisplayed);
       }
   }
   ```

### 运行测试

1. **运行所有测试**：
   ```bash
   mvn test
   ```

2. **运行特定测试类**：
   ```bash
   mvn test -Dtest=PlaywrightPageTest
   ```

3. **运行特定测试方法**：
   ```bash
   mvn test -Dtest=PlaywrightPageTest#shouldNavigateToUrlSuccessfully
   ```

4. **运行集成测试**：
   ```bash
   mvn test -Dtest="*IntegrationTest"
   ```

5. **生成测试报告**：
   ```bash
   mvn jacoco:report
   ```

### 测试覆盖率

我们要求：

- 新代码的测试覆盖率至少为 80%
- 核心模块的测试覆盖率至少为 90%
- 所有公共 API 必须有测试覆盖

### 文档规范

1. **Markdown 格式**：
   - 使用标准 Markdown 语法
   - 使用相对链接引用其他文档
   - 代码块指定语言类型

2. **文档结构**：
   - 使用清晰的标题层次
   - 提供目录导航
   - 使用表格和列表组织内容

3. **代码示例**：
   - 提供完整可运行的示例
   - 添加必要的注释
   - 包含前置条件和预期结果

1. **创建文档分支**：

   - 检查链接和语法
   - 预览文档效果

   ```bash
   git add wiki/new-guide.md

   ```

4. **创建 Pull Request**：
   - 选择文档作为审查者
   - 提供文档更改摘要

## 🐛 问题报告

### 报告 Bug

1. **检查现有问题**：
   - 在 GitHub Issues 中搜索类似问题
   - 避免重复报告

2. **创建新问题**：
   - 使用 Bug 报告模板
   - 提供详细的信息

3. **Bug 报告模板**：
   ```markdown
   ## Bug 描述
   简要描述 bug 的情况
   
   ## 复现步骤
   1. 执行操作 A
   2. 点击按钮 B
   3. 观察结果 C
   
   ## 期望行为
   描述您期望发生的情况
   
   ## 实际行为
   描述实际发生的情况
   
   ## 环境信息
   - OS: [例如 Windows 10]
   - Java 版本: [例如 17]
   - Midscene Java 版本: [例如 1.0.0]
   - 浏览器: [例如 Chrome 120]
   - 设备: [例如 Android 13]
   
   ## 附加信息
   - 错误日志
   - 截图
   - 代码示例
   ```

### 提供信息

1. **错误日志**：
   - 提供完整的错误堆栈
   - 包含相关的日志输出

2. **环境信息**：
   - 操作系统版本
   - Java 版本
   - Midscene Java 版本
   - 相关依赖版本

3. **最小复现代码**：
   - 提供能复现问题的最小代码示例
   - 确保代码可独立运行
