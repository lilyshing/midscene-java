## 🔄 数据流向

Midscene Java 中的数据流向体现了各核心组件之间的交互关系：

```
用户指令
    ↓
Agent (接收指令)
    ↓
Insight (分析指令，生成策略)
    ↓
AIModelService (调用 AI 模型)
    ↓
PlatformInterface (执行平台操作)
    ↓
基础设施层 (实际执行)
    ↓
结果返回 → Agent → 用户
```

## 🎯 设计原则

### 1. 自然语言驱动
Midscene Java 的核心设计理念是使用自然语言作为自动化操作的输入，而非传统的代码脚本。这使得自动化更加直观、易读且易于维护。

### 2. AI 智能决策
框架依赖 AI 模型进行智能决策，包括元素识别、操作规划和结果验证，大大降低了传统自动化中需要手动编写选择器和处理复杂场景的难度。

### 3. 平台抽象统一
通过 PlatformInterface 抽象层，Midscene Java 提供了跨平台的统一 API，使开发者可以用相同的代码操作不同的平台（Web、Android、桌面应用）。

### 4. 可扩展性
框架设计为高度可扩展，支持自定义 AI 模型适配器、平台实现和操作策略，满足各种特定场景的需求。

## 🧩 组件交互

### Agent 与 Insight 的交互
Agent 接收用户指令后，委托 Insight 进行智能分析。Insight 解析指令意图，生成执行策略，并将策略返回给 Agent。

### Agent 与 AIModelService 的交互
Agent 通过 AIModelService 调用 AI 模型，发送请求并处理响应。AIModelService 负责模型适配、请求管理和响应解析。

### Agent 与 PlatformInterface 的交互
Agent 将操作指令传递给 PlatformInterface，由 PlatformInterface 转换为特定平台的实际操作，并返回执行结果。

### Insight 与 AIModelService 的交互
Insight 可能需要调用 AI 模型进行语义理解和策略生成，这些调用通过 AIModelService 进行。

## 🌟 核心优势

### 1. 降低自动化门槛
传统自动化需要编写复杂的定位器和操作代码，Midscene Java 使用自然语言描述，大大降低了学习成本。

### 2. 提高维护性
自然语言描述的自动化脚本更易读、易理解，便于团队协作和长期维护。

### 3. 增强鲁棒性
AI 模型的智能决策使自动化能够更好地应对界面变化和异常情况，提高测试的稳定性。

### 4. 跨平台一致性
统一的 API 使开发者可以用相同的逻辑操作不同平台，减少学习成本和代码重复。
